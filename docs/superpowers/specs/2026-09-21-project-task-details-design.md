# 项目与待办详情设计

## 目标

给项目和待办补充可选的上下文说明，帮助以后回忆背景、执行要点和链接，同时不让日常清单变得臃肿。

## 范围与取舍

- 新增一个可选的多行 `details` 文本字段，分别存放在项目和待办记录中。
- 不新增标签、附件、评论、操作历史或独立详情页。
- 保持现有的标题、阶段、下一步、卡点、优先级、截止日与关联项目行为不变。

## 交互

### 新建和编辑

- “新增项目”和“新增待办”表单各增加一个非必填的“详情”多行输入框。
- 项目和待办的编辑弹层提供相同字段，允许以后补充、修改或清空详情。
- 详情用于记录背景、目标、验收要点、补充步骤、关键链接或决策；标题仍只写一眼可识别的事项。

### 阅读

- 项目卡在存在详情时只显示一行经过截断的摘要，并提供“查看详情 / 收起详情”控制查看完整文本。
- 待办列表不默认增加详情行，避免清单变高；有详情的待办会显示一个低干扰的“详情”入口，按需展开全文。
- 没有详情的旧记录与新记录均不显示占位文案或多余控件。

## 数据与兼容性

- 前端向既有任务、项目对象直接写入可选字符串 `details`；不改变顶层快照、版本号或本地 API 结构。
- 服务端继续按原样保存任务与项目数组，因此详情会被自动写入 `tasks.json`、`projects.json`，也会包含在 ZIP 备份、恢复和合并导入中。
- 旧文件缺少 `details` 时视为无详情，不做迁移、不改写历史数据。
- 合并导入沿用现有“项目按名称、待办按标题”去重规则；同名/同标题而未导入的记录不会覆盖本机详情。

## 验收与验证

- 可以新建、编辑和清空项目/待办详情。
- 有详情时可按需展开阅读，无详情时页面布局不增加空白。
- 切换页面后未提交的项目详情草稿仍保留，和现有项目草稿一致。
- 保存、刷新、ZIP 导出与恢复后详情仍在。
- 既有烟雾测试继续通过，并新增详情输入、草稿保留和保存载荷断言。
