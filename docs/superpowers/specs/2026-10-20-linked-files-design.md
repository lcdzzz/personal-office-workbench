# 待办关联文件与目录

用户已确认使用本机原路径引用。每个待办的 `linkedFiles` 为可选数组，元素为 `{path, kind, note}`；kind 为 file 或 directory，note 为本次关联的经验说明。一个待办可关联多个路径，同一规范路径在该待办内去重。缺失字段按空数组处理。

新增与编辑待办提供可增删的类型、绝对路径、说明输入行。未保存的新建草稿随页面切换保留；编辑取消不修改原关联。完成、废弃、恢复不清除关联。解除关联和删除待办都不操作磁盘文件。

侧边栏新增“关联文件”，从所有待办实时汇总，同一路径一行，显示名称、路径和每个关联待办的状态、说明。搜索匹配路径、说明、待办标题，文件/目录可筛选。点击待办进入其编辑窗口。每个资源可复制路径或打开所在目录；目录打开自身，文件在文件管理器中定位。

路径按 POSIX/Windows 语法做词法规范化，不解析软链接。Windows 路径汇总时忽略大小写；POSIX 路径保留大小写。只接受绝对本地路径，拒绝 URL、控制字符和 Windows 设备路径。路径不存在仍可保存，打开时给出错误，便于保留历史经验和跨机器备份。

关联保存在现有 tasks.json，沿用现有保存流程、ZIP/JSON 导入导出；备份仅含路径和说明，不包含被关联文件内容。无独立文件索引，最后一条关联解除后资源自动从列表消失。

新增 POST /api/linked-files/reveal，正文为 `{taskId, path}`。仅接受准确的本机工作台 Origin/Host，对照已持久化待办关联验证路径，检查存在性与类型；用参数数组调用系统文件管理器，不执行关联文件。错误返回 400，跨来源请求返回 403。

macOS 目录明确交给 Finder，避免目录本身是 .app 包时启动应用。若 Finder 的打开调用失败，回退为在父目录中选中该目录。

验收覆盖新建、编辑取消/保存、移除、草稿切换、旧数据、汇总去重、搜索筛选、完成/废弃留存、重新加载、备份往返与打开目录接口；文件管理器调用使用 mock，真实 Windows 桌面行为不作为本机自动化验收结论。
